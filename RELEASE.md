# Release - Publishing waifufetch

This document covers the release process for waifufetch - bumping the version,
pushing to GitHub, and publishing to the Arch User Repository (AUR).

## Files

| File | Role |
|------|------|
| `PKGBUILD` | Arch Linux build recipe (pkgver, sha256sums) |
| `.SRCINFO` | AUR metadata (regenerate with `makepkg --printsrcinfo > .SRCINFO`) |
| `libwaifu.sh` | Shared library (VERSION at top, sourced by both) |
| `waifu` | Standalone image fetcher (sources libwaifu.sh) |
| `waifufetch` | Fetch + system info (sources libwaifu.sh) |

## Versioning

| Component | When to bump |
|-----------|--------------|
| **Patch** (1.0.0 -> 1.0.1) | Bug fixes only, no new features |
| **Minor** (1.0.1 -> 1.1.0) | New features, backward-compatible |
| **Major** (1.0.0 -> 2.0.0) | Breaking changes |

Update `VERSION` in:
- `libwaifu.sh` (top of file)
- `waifu` (sources libwaifu.sh)
- `waifufetch` (sources libwaifu.sh)

Update `pkgver` in:
- `PKGBUILD` (handled by release.sh)
- `.SRCINFO` (regenerated by release.sh)

## Prerequisites

Before releasing, verify:

- [ ] `git status` — working tree is clean
- [ ] `git branch` — on `main`
- [ ] `waifufetch --help` — usage text matches actual features
- [ ] `waifu --help` — usage text matches actual features
- [ ] `waifufetch nsfw --help` — NSFW help is accurate
- [ ] `waifu nsfw --help` — NSFW help is accurate
- [ ] `waifufetch --debug` — runs without errors
- [ ] `README.md` — examples and flags are up to date
- [ ] `PKGBUILD` — depends/optdepends match actual requirements
- [ ] SSH keys loaded: `ssh-add -l` shows keys for GitHub and AUR

## Release: release.sh

The automated script handles everything:

```bash
./release.sh 1.1.0
```

This will:

1. Update `VERSION` in `libwaifu.sh`, `waifu`, `waifufetch`, and `pkgver` in `PKGBUILD`
2. Commit and push the tag to GitHub (so the archive URL is valid)
3. Download the tarball from the now-existing tag and compute the real SHA256
4. Update `PKGBUILD` and `.SRCINFO` with the correct SHA
5. Push the SHA fix to GitHub + AUR

This two-commit flow avoids GitHub's archive regeneration issue where
archives for the same tag can have different SHA256 hashes at different times.

## Release: Manual steps

If you prefer to do it manually or the script fails:

### 1. Commit and tag

```bash
git add libwaifu.sh waifu waifufetch PKGBUILD .SRCINFO README.md
git commit -m "v1.1.0: feature description"
git tag v1.1.0
```

### 2. Push to GitHub

```bash
git push origin main --tags
```

### 3. Update PKGBUILD

Edit `PKGBUILD`:
- `pkgver=1.1.0`
- `pkgrel=1`
- SHA256 for the tarball (get it from the GitHub release page or download + checksum)

### 4. Update .SRCINFO

```bash
makepkg --printsrcinfo > .SRCINFO
```

### 5. Push to AUR

```bash
cd /tmp
git clone ssh://aur@aur.archlinux.org/waifufetch.git waifufetch-aur
cd waifufetch-aur
cp /path/to/waifufetch/{PKGBUILD,.SRCINFO} .
git add PKGBUILD .SRCINFO
git commit -m "v1.1.0"
git push origin master
rm -rf /tmp/waifufetch-aur
```

## Policy

Only the project owner (**JGH0**) pushes updates to AUR and GitHub tags.
Pull requests improving the code are welcome, but the actual publishing
is done exclusively by JGH0 or someone with the necessary permissions.

If you find an outdated version on AUR, open an issue on GitHub.
Do not fork and push your own version to AUR.
